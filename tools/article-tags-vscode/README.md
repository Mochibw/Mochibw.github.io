# 文章标签补全

为当前工作区 `src/content/` 下所有子目录中的 Markdown、MDX 文章提供标签补全。无需启动 Astro、联网或提交 Git。

## 安装

在网站项目根目录的终端执行：

```powershell
code --install-extension .\tools\article-tags-vscode\article-tags-0.1.0.vsix --force
```

也可以在 VS Code 扩展面板右上角选择“从 VSIX 安装”，选中上述文件。若当前窗口未立即启用扩展，在命令面板执行 `Developer: Reload Window`（开发人员：重新加载窗口）。扩展仅在受信任、包含 `src/content/` 目录的工作区运行。

安装文件由本地源码打包生成，未发布到扩展市场。换电脑或重新克隆后，可按下面的开发步骤重新打包。

## 写作

```yaml
---
title: 示例文章
tags: ["读书", "感悟", "余华"]
---
```

在 `tags` 数组中输入时会弹出候选；没有自动弹出时可用 `Ctrl+Space`，或执行命令面板中的 `Trigger Suggest`（触发建议）。中文输入法若占用了快捷键，可通过命令面板触发。可以继续输入任何新标签，不受已有候选限制。

原有 `tags: [读书, 感悟, 余华]` 和多行列表同样受支持。补全插入的标签统一使用双引号，并正确转义引号、反斜杠等字符。扩展不会主动重写文章格式，也不会修改正文。当前文章已选择的其他标签不重复推荐；正在编辑的那个标签仍可被补全。

## 索引与同步

生成位置：项目根目录的 `.vscode/article-tags.json`，其中 `tags` 数组就是所有已保存文章实际标签的去重并集。该文件已被 Git 忽略，可以查看，但应通过文章修改标签。删除索引后可随时重建。

- 打开项目时全量扫描，缓存文件不作为文章之外的独立标签来源。
- 保存文章时重新扫描全部文章；手动保存、全部保存、自动保存均适用。未保存的编辑不更新索引。
- 新增、删除、重命名、移入或移出文章，以及 Git 切换分支、外部程序修改文章后，通过文件监听同步。
- 替换或删除标签后，只要其他文章也不再使用，该标签就从索引中移除；移除最后一篇文章后，索引成为空数组。
- 只收录开头 YAML frontmatter 的顶层 `tags`；不扫描正文、嵌套对象或 `drop_content/`。新建的任意内容子目录都在扫描范围内。
- 标签首尾空白会被去除，空字符串被忽略；内部空格与大小写保留。`AI` 与 `ai` 为两个标签。数组应只包含字符串，数字、`true`、`null` 等标签需要加引号。清空时使用 `tags: []`，也可以移除整个 `tags` 字段。
- 任何文章的 frontmatter 或标签解析失败时，整个索引保留上一次有效结果，并在“问题”面板定位错误；修复并保存后重新扫描全部文章，成功即替换索引并清除错误。
- 索引使用固定排序，仅在内容改变时写入。连续文件事件合并处理，扫描依次执行，避免旧结果覆盖新结果。

首次启动时如果存在解析错误且没有缓存，候选暂时为空；修复后自动恢复。缓存存在时，则暂时使用上一次有效候选。该扩展不会把标签库变成 Astro 的校验白名单。

## 命令

在命令面板中可以执行：

- `文章标签：查看标签索引`
- `文章标签：重建索引`

扫描记录可在“输出”面板的“文章标签”频道查看。索引若存在未保存的手动编辑，会暂缓覆盖并提示；撤销或保存后执行重建即可。

```powershell
npm ci
npm test
npm run build
npm run test:host -- "D:\Microsoft VS Code\Code.exe"
npm run package
```

将测试命令中的 VS Code 路径替换为本机路径。集成测试在临时目录使用隔离的工作区、用户配置和扩展目录，不改动真实文章。安装包包含已打包的运行代码和 YAML 依赖，安装后无需额外安装 npm 依赖。VSIX、构建产物、node_modules 和生成的索引均不纳入 Git。

运行时仅使用 VS Code API、Node.js 内置模块与 `yaml` 解析器；不引入语言服务器、CMS 或 Git hook。第三方许可见 `THIRD_PARTY_NOTICES.txt`。
